# Wordflect Organization Transition Guide

**Status**: Wordflect was built with personal Apple Developer account  
**Action Required**: After organization transition, update Wordflect configuration

---

## 📋 What Needs to Be Updated

### 1. App Store Connect (If Published)

If Wordflect is published or in TestFlight:

- [ ] **Transfer App to Organization**
  - Go to [App Store Connect](https://appstoreconnect.apple.com)
  - Navigate to Wordflect app
  - Transfer app to organization account (if applicable)
  - Note: App transfers require approval and may take time

- [ ] **Update Team ID**
  - Get new Team ID from organization account
  - Update in Xcode project settings
  - Location: Xcode → Project → Signing & Capabilities → Team

### 2. Xcode Project Configuration

- [ ] **Update Development Team**
  - Open Wordflect Xcode project
  - Go to **Signing & Capabilities** tab
  - Select organization team from dropdown
  - Xcode will auto-generate new provisioning profiles

- [ ] **Verify Bundle ID**
  - Bundle ID should remain the same (no change needed)
  - Verify it's still available under organization account
  - If conflicts, may need to register new bundle ID

- [ ] **Update Provisioning Profiles**
  - Xcode should auto-update when team is changed
  - If manual: Download new profiles from Apple Developer Portal
  - Delete old personal account profiles

### 3. Certificates & Signing

- [ ] **Development Certificates**
  - New certificates will be auto-generated by Xcode
  - Or download from [Apple Developer Portal](https://developer.apple.com/account/resources/certificates/list)
  - Under organization account

- [ ] **Distribution Certificates** (If Published)
  - Create new distribution certificate under organization
  - Update in Xcode → Signing & Capabilities
  - Required for App Store builds

- [ ] **App-Specific Passwords** (If Using)
  - Generate new app-specific passwords under organization account
  - Update in any CI/CD or automation tools

### 4. Backend Services (No Changes Needed)

✅ **Lambda Functions**: No changes required
- `wordflect-backend-dev-signin` - continues working
- `wordflect-backend-dev-signup` - continues working
- These don't use Apple certificates

✅ **API Gateway**: No changes required
- Endpoints continue working
- No Apple Developer dependencies

✅ **AWS Resources**: No changes required
- DynamoDB tables, S3 buckets, etc. are independent
- No Apple Developer account dependencies

### 5. Push Notifications (If Using)

- [ ] **APNs Certificates** (If Using Push Notifications)
  - Create new APNs certificate under organization account
  - Update in backend service (if storing certificates)
  - Update in AWS Secrets Manager (if storing there)

- [ ] **APNs Key** (If Using Key-Based Auth)
  - Generate new APNs key under organization account
  - Update in backend service
  - Update in AWS Secrets Manager

## 🔄 Step-by-Step Process

### Step 1: Verify Organization Account Access
1. Log into [Apple Developer Portal](https://developer.apple.com/account)
2. Confirm you have admin access to organization account
3. Note the new **Team ID** (different from personal account)

### Step 2: Update Xcode Project
1. Open Wordflect Xcode project
2. Select project in navigator
3. Go to **Signing & Capabilities** tab
4. Under **Team**, select organization account
5. Xcode will prompt to update provisioning profiles - click **Enable Automatic Signing**

### Step 3: Verify Build Settings
1. Check **Bundle Identifier** - should remain the same
2. Check **Development Team** - should show organization team
3. Check **Provisioning Profile** - should auto-update
4. Build project to verify signing works

### Step 4: Test Build
1. Build for simulator (no signing needed)
2. Build for device (tests signing)
3. Archive for TestFlight/App Store (tests distribution signing)

### Step 5: Update App Store Connect (If Published)
1. If app is published, transfer to organization account
2. Or create new app listing under organization
3. Update any CI/CD pipelines with new team ID

## ⚠️ Important Notes

### Bundle ID Considerations
- **Keep Same Bundle ID**: If possible, keep the same bundle ID
- **Transfer vs. New**: Transferring app keeps bundle ID, creating new requires new bundle ID
- **User Impact**: New bundle ID = new app (users would need to reinstall)

### Team ID Changes
- **Old Team ID**: Personal account team ID
- **New Team ID**: Organization account team ID
- **Update Required**: Xcode project, CI/CD, any hardcoded references

### Timeline
- **Organization Approval**: Wait for Apple to approve organization account
- **App Transfer**: Can take 24-48 hours if transferring existing app
- **Certificate Generation**: Immediate once organization is active

### Backward Compatibility
- **Old Builds**: Builds signed with personal account will continue to work
- **New Builds**: Must use organization account for new builds
- **TestFlight**: May need to create new TestFlight group under organization

## 🆘 Troubleshooting

### Error: "No provisioning profile found"
- **Solution**: Enable automatic signing in Xcode, or manually download profiles from Apple Developer Portal

### Error: "Bundle ID not available"
- **Solution**: Bundle ID may be registered under personal account. Either transfer app or register new bundle ID

### Error: "Team ID mismatch"
- **Solution**: Update Team ID in Xcode project settings and rebuild

### Backend Still Works?
- **Yes**: Lambda functions and API Gateway don't depend on Apple Developer account
- Only iOS app signing is affected
