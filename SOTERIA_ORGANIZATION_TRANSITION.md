### 4. Apple Wallet Configuration ⚠️ **CRITICAL**

Soteria uses Apple Wallet for member cards. This requires specific updates:

#### Pass Type ID Certificate
- [ ] **Register Pass Type ID** (if not already done)
  - Go to [Apple Developer Portal - Identifiers](https://developer.apple.com/account/resources/identifiers/list/passTypeId)
  - Verify `pass.com.soteria.member` exists under organization account
  - If missing, create new Pass Type ID under organization

- [ ] **Create New Pass Type ID Certificate**
  - Go to [Apple Developer Portal - Certificates](https://developer.apple.com/account/resources/certificates/list)
  - Create new Pass Type ID certificate under organization account
  - Download and install in Keychain
  - Export as `.p12` file with password

- [ ] **Update Lambda Environment Variables**
  - File: `lambda/soteria-apple-wallet-pass/index.js`
  - Update `TEAM_IDENTIFIER` environment variable
  - Location: AWS Lambda → Function Configuration → Environment Variables
  - **Old Team ID**: `4P5YXTJ7U7` (or current individual account ID)
  - **New Team ID**: `[YOUR_ORGANIZATION_TEAM_ID]`

**Update Lambda Environment**:
```bash
aws lambda update-function-configuration \
  --function-name soteria-apple-wallet-pass \
  --environment "Variables={
    PASS_BUCKET=soteria-wallet-passes,
    PASS_TYPE_ID=pass.com.soteria.member,
    CERT_PASSWORD=your_certificate_password_here,
    USER_DATA_TABLE=soteria-user-data,
    TEAM_IDENTIFIER=[YOUR_NEW_ORGANIZATION_TEAM_ID]
  }" \
  --region us-east-1
```

- [ ] **Upload New Certificate to S3**
  ```bash
  # Upload new Pass Type ID certificate
  aws s3 cp cert.p12 s3://soteria-wallet-passes/certificates/cert.p12 --region us-east-1
  ```

## 🔄 Step-by-Step Process

### Step 1: Verify Organization Account Access
1. Log into [Apple Developer Portal](https://developer.apple.com/account)
2. Confirm you have admin access to organization account
3. Note the new **Team ID** (different from personal account)
4. Verify organization has all required agreements signed

### Step 2: Update Xcode Project
1. Open `soteria.xcodeproj` in Xcode
2. Select project in navigator
3. Go to **Signing & Capabilities** tab
4. Under **Team**, select organization account
5. Xcode will prompt to update provisioning profiles - click **Enable Automatic Signing**
6. Verify Bundle ID is still `io.montebay.soteria`

### Step 3: Update Apple Wallet Configuration
1. Register/verify Pass Type ID `pass.com.soteria.member` under organization
2. Create new Pass Type ID certificate under organization account
3. Download certificate and export as `.p12`
4. Upload to S3: `s3://soteria-wallet-passes/certificates/cert.p12`
5. Update Lambda environment variable `TEAM_IDENTIFIER` with new organization Team ID
6. Test Apple Wallet pass generation

### Step 4: Verify Build Settings
1. Check **Bundle Identifier** - should be `io.montebay.soteria`
2. Check **Development Team** - should show organization team
3. Check **Provisioning Profile** - should auto-update
4. Build project to verify signing works

### Step 5: Test Build
1. Build for simulator (no signing needed)
2. Build for device (tests signing)
3. Archive for TestFlight/App Store (tests distribution signing)
4. Test Apple Wallet pass generation and download

### Step 6: Update App Store Connect (If Published)
1. If app is published, transfer to organization account
2. Or create new app listing under organization
3. Verify subscription products are configured
4. Update banking/tax information if needed

## 🆘 Troubleshooting

### Issue: "No provisioning profile found"
**Solution**: 
1. In Xcode, go to Signing & Capabilities
2. Uncheck and re-check "Automatically manage signing"
3. Select organization team again
4. Clean build folder (Cmd+Shift+K) and rebuild

### Issue: "Bundle ID already exists"
**Solution**: 
1. The bundle ID should transfer with the app
2. If not, you may need to register it under organization account
3. Or use a new bundle ID (requires app re-submission)

### Issue: Apple Wallet passes not generating
**Solution**:
1. Verify Pass Type ID is registered under organization
2. Verify certificate is updated in S3
3. Verify `TEAM_IDENTIFIER` in Lambda matches organization Team ID
4. Check Lambda logs for specific errors

### Issue: "Team ID mismatch" in Apple Wallet
**Solution**:
1. Verify Lambda `TEAM_IDENTIFIER` environment variable matches organization Team ID
2. Verify Pass Type ID certificate was created under organization account
3. Re-upload certificate to S3 if needed
